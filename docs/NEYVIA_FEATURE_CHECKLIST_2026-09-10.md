# Neyvia implementation and discovery checklist

Reviewed 2026-09-10 against the current implementation, this conversation's requests, the system scope reference, and preserved receipts. This supersedes the earlier statement that only the NAS login check remained. The larger programme has working features **and substantial unfinished ambitions**.

`[x]` means the described, bounded capability has implementation and relevant verification. `[ ] Partial` means a useful implementation exists but the full requested experience is incomplete. `[ ] Unproven` means the broader claim has not been established. Finding a component, schema, install, or passing check does not prove a whole product journey.

The subsequent [product polish pass](NEYVIA_PRODUCT_POLISH_2026-09-10.md) applies these capabilities across the visible workspaces and adds startup recovery/cache repairs. It is published as `6c16489`; the earlier evidence below remains scoped to its recorded journeys.

## Harness discovery inventory

The implemented adapters are Neyvia Native, Hermes, OpenClaw, Codex CLI, Claude Code, Grok Build, Kimi Code, OpenCode, Cursor Agent, Prime Agent, Pi, DeepSeek Harness, gptme, Rook and Wallbreaker. Neyvia Hybrid is the additional orchestration entry, not another provider account.

Main chat shows general-purpose adapters and explains security-only restrictions. Harnesses exposes configuration, install/auth state, per-route evidence and the authorized security path. An unavailable adapter remains discoverable without receiving a false ready label.

Gemini CLI, Qwen Code, Cline, Roo, Copilot, Goose, Amp, Factory Droid, Aider, Crush and newer OpenHands/SWE-agent integrations remain research candidates from earlier ecosystem planning, **not completed adapters**. Their earlier evaluations should be refreshed before implementation. No claim is made that every feature of every upstream harness has been copied.

## Cleanup and implementation improvements in this audit

- [x] Derive main runtime discovery from the backend catalog; retain only startup/legacy fallbacks for older backends.
- [x] Separate Hermes identity from Hybrid orchestration and remove the duplicate Hybrid-as-Hermes auth probe.
- [x] Prevent Hybrid's direct-chat control from claiming to run an orchestration.
- [x] Remove duplicated Native/Hybrid explanation cards and their unused CSS. Keep one compact explanation.
- [x] Load saved comparison reports only on opening Measured quality; avoid overlapping/hidden-tab job polls and slow idle polling from 1.8 seconds to 15 seconds.
- [x] Preserve batch-owned job receipts instead of pruning them out of their still-inspectable batch.
- [x] Prevent unchanged App Factory registrations from duplicating history/proofs or replacing the previous revision with the current revision.
- [x] Replace the Python pixel-by-pixel outside-region check with an equivalent all-channel image difference.
- [x] Preserve the parent's no-bytecode policy in spawned batch/job workers. A real NAS check caught cache files contaminating a sealed candidate; the replacement passes with no added files. The rejected candidate is retained.
- [ ] The entire repository has **not** been proven free of dead code. Large active shell modules, compatibility surfaces, release history and old proof were preserved. Deletion needs dependency and behavior evidence; absence from a recent tool-call window is not proof that a feature is useless.

## Evidence and release accounting

Preserved evidence lives in `proof/system-improvement/`: the original integration inventory and real Luna collaboration receipts; `harness-batch-checks.json` (26 scheduling/recovery/catalog/source-preservation checks); `visual-performance-checks.json` (same-image comparison and corruption controls); the audit UI/release receipts; and the final candidate file manifest.

The audit's smallest relevant checks include App Factory lineage/idempotency, visual specifications, batch scheduling/recovery, main-chat continuation, native failure recovery, 107 frontend checks and the production build. Browser inspection covers real catalog choices, preparation/cancellation, exact route, saved history, and viewport behavior. Live model outcomes are recorded separately from fixture checks.

The major remaining product work is therefore visible: universal recovery/rollback, full upstream harness feature coverage, physical device continuity, a complete precise-image/taste loop, a game make-and-test journey, and fair model-quality/performance experiments. This checklist is not a claim that those ambitions are finished.
