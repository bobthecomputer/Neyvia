The installed Codex generated schema advertises these 19 item variants: `userMessage`, `hookPrompt`, `agentMessage`, `functionCallOutput`, `plan`, `reasoning`, `commandExecution`, `fileChange`, `mcpToolCall`, `dynamicToolCall`, `collabAgentToolCall`, `subAgentActivity`, `webSearch`, `imageView`, `sleep`, `imageGeneration`, `enteredReviewMode`, `exitedReviewMode`, `contextCompaction`. The reasoning summary choices are `auto`, `concise`, `detailed`, `none`. Hook prompt fragments and function output text are retained; unknown future variants produce an explicit notice. Local schema discovery: `codex app-server generate-json-schema --experimental --out .agent_control/t22/protocol`.

All three adapters use the existing `Item` model. Reasoning carries exposed text, provider/source, exposure and availability; tools carry command, complete arguments, text output, structured result, exit code, duration and its source; diffs carry patch and scope. A replacement inferred from edit arguments is labelled as changed text; a Write without before-content is labelled as new content. Neither is presented as an observed full-file before state. Unknown measurements stay absent and command rows explicitly say they were not reported. Claude successful command results can establish exit zero; numeric provider results and errors take precedence. Durations from transcript/transport timestamps are labelled Observed.

Capture remains maximal for every display level. Settings > Thinking and actions controls presentation: Show everything (default), Summaries (expandable), Minimal (messages, failures and availability notices). `neyvia.view.transparency({level})` uses the same durable workspace bus and Settings control; `neyvia.view.transparency.state` observes its value without listing chats. The executable `transparency` manual checks that choice.

Registration: native view-tool definitions → workspace `view.*` dispatch → existing authenticated `/api/ui/tools/call` and generic desktop `call_native_tool_command` → existing Tauri `call_desktop_backend_command`; plugin MCP PORTED includes both transparency actions; manual index includes `transparency`. No new HTTP command or IPC allow-list entry is needed. Existing `connected_session_tool_output_command` gains Codex/OpenCode implementations; the thread calls it for expanded truncated output. Codex remembers the visible item's turn so earlier-page output is addressed directly, with a bounded recent-turn search for unlocated live items.

Transport bounds are explicit: adapters retain up to 256 Ki characters per text payload, pages carry 8 Ki characters of tool output, full-output requests allow 1,000,000 characters. The event ring caps each live event at 64 KiB; a clipped event displays an availability notice and coalesces a fresh authoritative thread read instead of applying an incomplete payload. Structured data and diffs label truncation; providers may themselves redact or shorten output before Neyvia sees it. Display controls do not change model effort, token budget, selected provider or global CLI configuration.
