# Clarify and Create

Use for open creative work, unclear product ambitions, and requests for varied or innovative outcomes. A precise implementation task or simple factual question does not need a discovery exercise. Keep the user's ambition; missing detail is a reason to make uncertainty visible and explore useful possibilities.

## Establish enough understanding to act

Read the relevant conversation and available artifact first. Briefly state the intended outcome and distinguish explicit requirements, tentative interpretations, and unanswered questions. Correct an interpretation when evidence changes; do not claim certainty or agreement the user has not supplied.

Ask early about missing information that could materially change the audience, purpose, experience, constraints, or acceptance criteria. Usually start with the most informative question and provide a concrete example or contrasting possibilities so the user can answer easily. Use the available question tool where appropriate. Do not repeat answered questions or make the user fill out a questionnaire before seeing anything useful.

Continue independent work while an answer is pending. If the missing answer only affects reversible exploration, label a reasonable assumption and develop candidates. If it determines a consequential action or required authority, keep that action pending. Elapsed time and a preselected option are not consent. Respect a user's request to proceed without further questions wherever existing authority permits.

## Three useful interaction patterns

**Contrast to clarify.** Show a small, decision-changing contrast: two example interactions, opening paragraphs, compositions, or user journeys. Ask which experience fits and why. A choice provides evidence about that decision, not blanket approval or a permanent inferred preference.

**Create a direction portfolio.** When the request is open, offer a few substantively different directions, often two or three. Vary the interaction model, mechanism, composition, or value proposition rather than only colors and adjectives. Give each a concrete example, the user benefit, its main assumption, and a meaningful tradeoff. Use compact sketches or text first; generate expensive assets or working variants only when they resolve a real uncertainty within the task's budget. Do not spawn agents merely to produce variety.

**Check understanding at a turning point.** After a material correction, candidate choice, or discovered constraint, show the updated understanding and the next consequence. Ask for clarification only on the unresolved part. Carry chosen constraints into later passes, compaction, and handoffs without quietly shrinking the ambition. Do not turn each turn or reversible edit into an approval ceremony.

For concrete examples or when implementing these patterns in a product, read [interaction patterns](references/interaction-patterns.md).

## Work in the main flow

Use the current conversation and existing Preview or artifact surface. Do not require an advisor page or construct a new temporary UI by default. If the user elects an advisor, reuse a compact brief containing the outcome, decisions, alternatives, evidence, and open questions. Preserve route and effort choices; an advisor should add value to the existing work rather than restart discovery. This skill does not itself authorize delegation.

Once the direction is sufficiently clear, produce the requested artifact or implement the authorized work. Keep alternate directions retrievable when useful. Judge success by the fit and observable result; question count, asserted confidence, and number of variants are not quality measures.
