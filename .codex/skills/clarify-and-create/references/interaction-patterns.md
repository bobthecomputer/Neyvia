# Interaction patterns

Read when a concrete example would help or when implementing this behavior in a harness. These illustrate decisions; they are not mandatory scripts.

## A sparse creative request

For "make my workspace better," inspect the existing workspace first. If its intended users are unknown, ask who uses it and identify why that matters. Meanwhile, show distinct possibilities such as a work queue organized around the next action, an artifact canvas organized around the output, and a conversational workspace organized around decisions. Explain which observed friction each addresses. Do not assume the user wants all three or silently replace the entire application.

## A contrast that reveals preference

For "make this feel more innovative," show two brief examples of behavior: a system that suggests several next moves and a system that composes a useful operation from prior work. Ask which kind of improvement the user means. A response about behavior should not be reduced to a visual style preference.

## An execution request with enough context

For "fix the upload button; preserve the current screen," inspect and fix that path. Do not add a portfolio, ask the user to select a design philosophy, or route through an advisor. Ask only if an unresolved fact changes the required behavior or authority.

## Advisor amplification

When the user chooses an advisor, pass the established brief and the specific remaining decision. Incorporate advice as a proposed delta; preserve the user's decisions. Do not equate mentioning an advisor feature with authorizing additional model calls.

## Product implementation

Keep questions, candidate selection, and corrections attached to the active task. A dismissal is not an answer. A preference applies to its declared scope and can be changed. Handle unanswered questions, late replies, and task switches without applying an answer to the wrong task. A correction should update the brief's revision and dependent work.

Prefer a compact question or candidate row in the existing conversation. Reuse Preview for richer examples. Expose control over exploration depth when it changes cost or interaction; basic clarification should work without enabling an evaluative workspace. Collect only feedback the user has agreed to retain.

When evaluating this behavior, compare outcome fit, useful diversity, interventions, and total latency/cost. Include a precise prompt that should proceed immediately, a poor prompt that benefits from examples, a late correction, and a prompt with an authority boundary. More questions alone are not a gain.
