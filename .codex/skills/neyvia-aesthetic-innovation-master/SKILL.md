# Neyvia Aesthetic + Innovation Master

Use three internal modes.

## Taste

Choose calm hierarchy over decoration, tonal depth over border soup, semantic color over arbitrary chroma, native behavior over web-generic styling, and dense-but-readable composition over whitespace without purpose.

The primary object must win in under one second. Supporting navigation recedes. Color carries identity or state locally; it never recolors the entire product merely because orchestration is active. Healthy autonomous work may recede, while uncertainty, divergence, failed proof, and requested human judgment gain salience.

The current accepted Neyvia direction is an ink-navy canvas with one route blue for human action, focus, selection, and live work; a restrained north-star gold identifies Neyvia's own voice and verified outcomes. Ship Geist and Geist Mono rather than naming unbundled fonts. Use one coherent icon family. Treat this as the user's current reference, not a reason to force dark colors when Light or System is selected: every theme must preserve the same roles and readable contrast. User-provided screenshots outrank this paragraph when they differ.

The September 2026 before/after screenshots show what this direction improves: a quiet one-line sidebar, a clear conversation as the primary object, a compact two-row phone composer, and route controls that remain reachable without a tower of buttons. Preserve those gains under long replies, an open menu, selected work, and a live stream. Keep the previewed app visible when displaying review evidence; a proof panel should not consume the whole workspace.

## Critic

The rendered result outranks the explanation. Use this loop:

> render → observe → diagnose causally → generate real alternatives → compare → revise → stress states → render again

Inspect first-glance hierarchy, visual mass, contrast topology, alignment, density, typography, geometry, state quality, reduced motion, long content, compact width, loading, failure, reconnect, and recovery. Do not call code or a static component gallery visual proof.

Use `preview.taste` to find measurable defects such as contrast, overlap, overflow, tiny targets, and typeface drift, then inspect its actual desktop and phone screenshots. A clean report or 100/100 score is only a defect-screening result, never a beauty verdict. Check the exact surface, theme, viewport, state, and build being claimed. If the review loaded a login page, failed request, or stale server, it did not inspect the intended UI. Re-render the same state after a correction; do not dismiss a flagged issue until the pixels explain it.

For streaming UI, compare an early pending frame, reasoning summary, mid-answer, and completed frame. Stable message identity, monotonic readable text, markdown, layout position, and reduced-motion behavior matter more than decorative effects. A fixture proves rendering mechanics; a live model turn and an installed-app run are separate claims. Never invent a thinking trace when the provider supplies only a summary.

## Inventor

Research broadly, including developer tools, operating systems, music and video software, industrial controls, cameras, editorial systems, and accessible interfaces. Extract the principle, not the surface. Start from a real tension in the work, then generate several interaction models.

Spend novelty only where Neyvia differs from conventional software. Ordinary navigation, typing, selection, and destructive confirmation should remain familiar. Prefer behavioral invention—how state appears, how control transfers, how time is navigated, how work compresses, and how proof attaches—over ornamental novelty.

## Neyvia territories

Explore especially:

- adaptive dimensionality: chat reveals orchestration structure only as parallel complexity appears;
- semantic activity compression: many low-level events become one compact, inspectable work object;
- shared-control presence: user and agent operate the same app with local, reversible ownership;
- temporal preview: scrub, compare, branch, and comment on generated states;
- proof-native UI: tests, screenshots, diffs, invariants, and receipts are first-class objects;
- attention topology: visualize required attention, not merely activity;
- capability apparition: advanced controls appear when context makes them useful, then recede;
- interruption continuity: preserve visual place, unresolved intent, ownership, and proof state after restart.

## Anti-slop gate

Reject rounded-card soup, badge inflation, helper-copy inflation, purple-as-AI, random gradients, arbitrary glass, icon circles everywhere, giant empty heroes, fake activity charts, permanent advanced controls, agent avatar zoos, and animated reasoning theater.

Also reject misleading theme controls, white-on-white fallbacks, hard-coded text colors that defeat tokens, redundant blinking cursors, and a visual review whose evidence overwhelms the artifact. If the lens catches a regression you introduced, repair it before celebrating the new direction.

## Minimum process

For important work:

1. Define the visual thesis and primary object.
2. Rank information as primary, secondary, tertiary, contextual, or hidden.
3. Use the user's references first; research a shipped comparison only when it can change the decision.
4. When the composition is materially weak, compare reduction, rehierarchy, and a real interaction alternative. Color swaps do not count.
5. Implement the strongest coherent candidate.
6. Render realistic states and run the critic.
7. Preserve screenshots and causal critique.
8. Verify keyboard, compact width, failure/recovery, and reduced motion.

Ask separately:

> Is every visible decision intentional?

and

> Does anything advance the interaction model rather than merely restyle it?

The target reaction is: **I have not seen it done exactly this way, but now that I have, it feels obvious.**
